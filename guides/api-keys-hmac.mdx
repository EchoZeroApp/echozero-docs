<Note>
Every call authenticated with an API key needs `x-api-key`, `x-timestamp` and `x-signature`. Sending only `x-api-key` returns 401. The `ezs_` secret is not optional.
</Note>

## API key authentication

Send your developer API key on every authenticated request in either header, **together with the signing headers** described below:

```bash
x-api-key: ez_live_...
# or
Authorization: Bearer ez_live_...
```

On its own, either header returns 401. The complete signed requests are in the `ez` helper and the curl examples further down. Do not copy a bare key-only request.

Create and revoke keys in the [Dev Portal](https://devportal.echozero.app). Each key has scoped permissions - request only the scopes your integration needs.

### Scopes

Each key carries scopes. The full list is in [Authentication overview](/guides/authentication#scopes); request only what your integration needs.

## Required REST HMAC signing

Every API-key authenticated request must be signed with the **API secret** returned when the key was created. JWT and OAuth bearer session tokens are exempt.

| Header | Description |
| --- | --- |
| `x-api-key` | Your API key id (`ez_live_...`) |
| `x-signature` | `HMAC-SHA256(secretKey, stringToSign)` as lowercase hex |
| `x-timestamp` | Epoch **milliseconds**; rejected if drift exceeds 5 minutes |

### String to sign

```
stringToSign = timestamp + METHOD + path + body
```

- `METHOD` - uppercase HTTP verb (`GET`, `POST`, …)
- `path` - full request path including query string (e.g. `/api/v1/developers/earnings`)
- `body` - the compact JSON for POST/PUT/PATCH (no spaces or line breaks between tokens), or an empty string when there is no body. The server signs `JSON.stringify` of the parsed body, so send compact JSON and sign exactly the string you send. A body with extra spaces or line breaks produces a 401.

<Warning>
REST HMAC uses **milliseconds** and includes the HTTP method and path. This is **different** from [inbound agent webhook](/guides/webhook-security) signing, which uses **seconds** and canonical JSON only.
</Warning>

### Signed request helper

Every REST example in these docs uses this small shell function. Paste it into your shell once, after exporting `EZ_API_KEY` and `EZ_SECRET`:

```bash
# Signed REST helper: ez METHOD PATH [JSON_BODY]
# Needs EZ_API_KEY (ez_live_...), EZ_SECRET (ezs_...) and jq. Works in bash and zsh.
# The body is compacted with jq -c, and that same compact string is signed and sent.
ez() {
  local method="$1" req_path="$2" body="${3:-}"
  local ts sig
  local args=()
  if [ -n "$body" ]; then
    body=$(printf '%s' "$body" | jq -c .) || return 1
    args=(-d "$body")
  fi
  ts=$(python3 -c 'import time;print(int(time.time()*1000))')
  sig=$(printf '%s' "${ts}${method}${req_path}${body}" | openssl dgst -sha256 -hmac "$EZ_SECRET" | awk '{print $NF}')
  curl -sS -X "$method" "https://mcp.echozero.app${req_path}" \
    -H "x-api-key: $EZ_API_KEY" \
    -H "x-timestamp: $ts" \
    -H "x-signature: $sig" \
    -H "x-ez-mcp-client: ${EZ_CLIENT:-my-integration}" \
    -H "Content-Type: application/json" \
    "${args[@]}"
}
```

```bash
ez GET /api/v1/users/me
ez POST /api/v1/wallet/mode '{"isVirtualMode":true}'
```

Pass the path exactly as you want it requested, including any query string, because the query string is part of the signed text. The helper compacts your JSON with `jq -c` and signs and sends that same compact string, because the server signs `JSON.stringify` of the parsed body. The `x-ez-mcp-client` header carries a short label for your client (set `EZ_CLIENT` to change it). The API spec lists it as required on `POST /api/v1/agents`; whether it is enforced is not confirmed, so send it on agent create calls.

<Note>
The timestamp comes from `python3` on purpose. `date +%s%3N` only works on GNU/Linux. On macOS it prints a literal `N`, and the call fails with `Invalid x-timestamp value`. A perl one-liner such as `perl -MTime::HiRes=time -e 'printf "%d", time*1000'` works too.
</Note>

### curl example (GET)

The helper above does the following, written out step by step:

```bash
API_KEY="ez_live_..."
SECRET="ezs_..."   # secret shown once at key creation
TS=$(python3 -c 'import time;print(int(time.time()*1000))')
REQ_PATH="/api/v1/users/me"
SIG=$(printf '%s' "${TS}GET${REQ_PATH}" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $NF}')

curl -sS "https://mcp.echozero.app${REQ_PATH}" \
  -H "x-api-key: $API_KEY" \
  -H "x-timestamp: $TS" \
  -H "x-signature: $SIG"
```

### curl example (POST)

This example posts to the sandbox signal simulator, which has no side effects. Use an agent id you own.

```bash
API_KEY="ez_live_..."
SECRET="ezs_..."
TS=$(python3 -c 'import time;print(int(time.time()*1000))')
REQ_PATH="/api/sandbox/agents/$AGENT_ID/signals/simulate"
BODY='{"message":"BUY SOL $50"}'
SIG=$(printf '%s' "${TS}POST${REQ_PATH}${BODY}" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $NF}')

curl -sS -X POST "https://mcp.echozero.app${REQ_PATH}" \
  -H "x-api-key: $API_KEY" \
  -H "Content-Type: application/json" \
  -H "x-timestamp: $TS" \
  -H "x-signature: $SIG" \
  -d "$BODY"
```

### Python (echozero-sdk)

```python
import os
from echozero import EchoZeroClient

client = EchoZeroClient(
    api_key=os.environ["EZ_API_KEY"],
    hmac_secret_key=os.environ["EZ_SECRET"],
)
me = client.get("/api/v1/users/me", hmac=True)
print(me)
```

`hmac=True` is the default for API-key clients, so every request is signed automatically.

### TypeScript (echozero-sdk)

```typescript
import { EchoZeroClient } from '@echozero/sdk';

const client = new EchoZeroClient({
  apiKey: process.env.EZ_API_KEY!,
  hmacSecretKey: process.env.EZ_SECRET,
});

const me = await client.get('/api/v1/users/me', { hmac: true });
```

The SDK signs every API-key request by default when `hmacSecretKey` is configured.

Or sign manually with `signRestRequest`:

```typescript
import { signRestRequest } from '@echozero/sdk';

const headers = await signRestRequest({
  secretKey: process.env.EZ_SECRET!,
  method: 'GET',
  path: '/api/v1/users/me',
});
// headers['x-timestamp'], headers['x-signature']
```

## HMAC error responses

| Condition | HTTP | Message |
| --- | --- | --- |
| Missing `x-signature` (API key auth) | 401 | Missing x-signature header |
| Missing `x-timestamp` | 401 | Missing x-timestamp header |
| Non-numeric timestamp | 401 | Invalid x-timestamp value |
| Timestamp > 5 min drift | 401 | Request timestamp expired |
| Wrong signature | 401 | Invalid HMAC signature |
| Key has no secret | 401 | API key does not support HMAC signing |

## MCP authentication

API keys (with required HMAC) work on `POST https://mcp.echozero.app/mcp` the same way as REST. Send `x-api-key` or `Authorization: Bearer` on every MCP call, including `initialize`. See the [MCP Server guide](/guides/mcp).
